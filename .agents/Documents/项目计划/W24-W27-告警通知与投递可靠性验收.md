# W24–W27 告警通知与投递可靠性验收

日期：2026-10-03

范围：Phase 3 W24–W27。为 W21–W24 已生成的告警事件配置 Webhook / SMTP Email 通知，持久化投递任务并支持自动重试、失败查看和人工重试。

## 验收边界

- 渠道按项目、环境范围和最低告警级别匹配；创建新告警事件时与事件在同一 PostgreSQL 事务内入队。相同未解决事件后续出现新 Span 时不重复发送。
- Collector 只持久化通知任务，不执行网络投递。独立 API worker 负责发送；Webhook / SMTP 慢、超时或不可用不能扩大业务请求或 Collector 的外部发送等待。
- 投递队列在进程重启后可恢复，并支持有限次数退避重试、最终失败状态和失败任务人工重试。外部投递为至少一次语义；若远端已接受而本地确认前进程崩溃，重试可能导致远端重复收到，Webhook 提供稳定投递 ID 供接收方去重。
- 浏览器通过现有同源开发代理访问管理接口；管理员令牌不进入浏览器。数据库不明文保存 Webhook URL 等敏感目标，不向列表、错误响应或日志回显秘密。
- SMTP 服务端参数来自环境配置。Mailpit 仅作为本地 SMTP 捕获器，管理界面和 SMTP 端口仅绑定 loopback；它不是生产邮件服务。

## 测试结果

| 检查 | 结果 |
| --- | --- |
| 全仓构建 / 类型检查 | 通过：`pnpm build` |
| 后端渠道、队列、权限及安全单测 | 通过：API 158 项，Collector 19 项；各有 1 项既有 opt-in 集成用例跳过 |
| 前端 API 代理与界面单测 | 通过：76 项 |
| PostgreSQL 入队、项目隔离、失败重试与进程恢复 | 通过：真实本地 PostgreSQL 验收；重启 API 后排队任务恢复并送达 |
| Mailpit SMTP 真链路检查 | 通过：API worker 经 SMTP 投递到本机 Mailpit 并核对邮件；只清理本轮唯一收件人和消息 |
| Playwright 页面/API 验收 | 通过：项目渠道、测试发送、人工重试送达、管理令牌留在服务端、窄屏无横向溢出 |
| 敏感值检查与资源清理 | 通过：进程输出无敏感值；隔离项目、临时服务和本轮邮件均清理成功 |

复审补强了两处保护：单字符邮箱摘要也会打码；私有 Webhook 目标开关只有在 `NODE_ENV=development` 或 `test` 时生效。浏览器实测还发现并修复投递历史只在进入页面时读取一次的问题：历史页打开期间每 3 秒刷新一次投递状态。截图见 `output/playwright/w24-27-notifications.png`。API 与 Collector 各跳过的 1 项是已有、需单独 opt-in 的其他集成用例；本轮 W24–W27 的 PostgreSQL / Mailpit 验收由独立脚本实际执行并通过。

## 不包含

本轮不实现项目成员 RBAC、短信/即时通讯专用适配器、每项目独立 SMTP 账户、可编辑告警规则、通知 SLA 或生产容量上线门。Webhook 作为通用 HTTP 回调渠道；Email 使用服务端 SMTP 配置。
