# W26–W29 项目隔离与隐私审计验收

日期：2026-10-03
范围：项目级访问凭证、跨项目隔离、敏感字段策略、关键配置审计、服务接入配置。
结论：本地开发与集成验收通过；成员登录与角色 RBAC 尚未交付，不能据此作为生产权限验收。

## 交付内容

- **项目凭证与隔离**：项目 API key 仅允许一个 scope：`spans:write` 或 `trace:read`。写入凭证不能读取 Trace；读取凭证不能写入 Span。Trace 查询须显式指定 `projectId`，服务端按凭证所属项目核对，跨项目读取返回拒绝。项目停用、凭证撤销后访问失效。
- **凭证生命周期**：凭证以 SHA-256 摘要入库；创建/轮换只返回一次明文，列表仅返回前缀和元数据。轮换在单条数据库语句中撤销旧凭证并创建新凭证；撤销可重复调用。
- **隐私策略**：每个项目有默认策略，Prompt/Response 原文采集不可开启。可维护最多 64 个大小写不敏感的额外脱敏字段。Span attributes 在发送到 Kafka 前递归过滤；Span `error` 自由文本不转发。策略缺失或格式异常时拒绝接收，避免回退到无脱敏路径。
- **审计与接入配置**：服务创建、凭证创建/轮换/撤销、隐私策略变更写入追加式审计记录；对外审计列表只返回安全投影和分页结果，不暴露凭证、配置内容或请求正文。项目设置页包含服务、凭证、隐私策略与审计真实 API；Trace 保留周期在没有真实读写接口时保持只读，不显示演示值。
- **前端边界**：管理写请求经同源代理并校验输入；切换项目时重新挂载面板、取消旧请求；一次性明文只在当前页面内存中显示，不写入持久化存储。

## 未完成边界

排期中的“角色最小权限”目前只落实到机器凭证 scope 和项目隔离。现有平台仅有全局 `PLATFORM_ADMIN_TOKEN`，缺少用户身份提供方、登录会话和可信 actor 身份；数据库既有 members 表尚未接入授权。审计 actor 因此使用 `platform_admin`，不能代表真实操作用户。需要先确定身份源与登录方式，再实现项目成员授权、角色矩阵和 actor 审计。用户确认身份模型之前，不将这部分标记为完成。
